# Repository Guidelines

## Project Structure & Module Organization

This repository is a Lua-based Neovim configuration. `init.lua` is the entrypoint and loads modules from `lua/config/` before plugin specs from `lua/plugins/`.

- `lua/config/lazy.lua`: bootstraps and configures lazy.nvim.
- `lua/config/options.lua`: editor options and defaults.
- `lua/config/keymaps.lua`: user keymaps loaded on `VeryLazy`.
- `lua/config/markdown.lua`: Markdown frontmatter timestamp automation.
- `lua/plugins/*.lua`: Lazy plugin specifications grouped by purpose.
- `lua/notebook/`: local edit-only `.ipynb` rendering and save support.
- `scripts/test-notebook.lua`: notebook round-trip regression test.
- `lazy-lock.json`: plugin lockfile generated by lazy.nvim.

There is no separate assets or test directory at this time.

## Build, Test, and Development Commands

- `nvim --headless "+Lazy! sync" +qa`: install/update plugins and refresh `lazy-lock.json`.
- `nvim --headless "+lua print('startup-ok')" +qa`: verify the config starts without errors.
- `luac -p init.lua lua/config/*.lua lua/plugins/*.lua lua/notebook/*.lua scripts/test-notebook.lua`: syntax-check Lua files.
- `nvim --headless "+checkhealth nvim-treesitter mason obsidian" +qa`: run targeted health checks.
- `nvim --headless -S scripts/test-notebook.lua +qa`: run the notebook round-trip regression test.

Run commands from the repository root: `/home/seth/.config/nvim`.

## Coding Style & Naming Conventions

Use Lua modules that return either a table or a small public module table. Keep plugin specs focused and grouped by domain, for example `editor.lua`, `lsp.lua`, and `markdown.lua`. Use two-space indentation in Lua tables and prefer descriptive local helper functions over large inline callbacks. Keep comments sparse and only add them where behavior is not obvious.

## Testing Guidelines

There is no formal test framework. Validate changes with `luac -p` and a headless Neovim startup check. For plugin changes, add a focused `checkhealth` run. For save hooks or autocmds, test the actual event path with a temporary file under `/tmp`. For notebook changes, run `nvim --headless -S scripts/test-notebook.lua +qa`.

## Commit & Pull Request Guidelines

This repository has no existing commit history, so use short imperative commit messages such as `Add markdown timestamp hook` or `Configure mini.pick window`. Pull requests should summarize the change, list validation commands run, and call out any required external tools or version requirements.

## Agent-Specific Instructions

Do not overwrite user-local paths or install system software without explicit approval. Keep `lazy-lock.json` changes only when plugin updates were intentionally run.

When changing keymaps, plugins, formatter settings, LSP settings, editor options, commands, or other user-visible configuration behavior, update `README.md` in the same change so the documented reference stays current.

After completing any request, spawn two subagents to review the work before stating that the work is completed:

- Magus: a professional Lua developer and Neovim maintainer who reviews runtime correctness, plugin integration, idiomatic Lua, and Neovim behavior.
- Sanders: a professional technical documentation writer and quality engineer who reviews documentation accuracy, validation coverage, edge cases, and handoff clarity.

Wait for both subagents to finish and incorporate or explicitly address their feedback before reporting completion.
